# 1. Brainstorm

**Purpose.** Settle the design fork before anyone writes code.

**Minimum form.** The sentence "no open design question" and move on. Most changes are this.

**Steps**
1. Read the decision index first (see project.md). A question an existing record answers is closed; say which record
   and move on. Reopen one only with a reason the record does not already address.
2. Name the real fork in one line. If there isn't one, you are in the minimum form.
3. Offer two or three options. For each: what it costs, what it forbids later, and who has to maintain it.
4. Recommend one, and say what would change your mind.
5. Keep it short. This is a paragraph, not a document.

**Exit.** The owner's choice, in one line, plus a note of whether it is a decision-record candidate — that is, whether
a later session could plausibly undo it and nothing in the code would tell them not to.

**Who.** The lead session thinks and writes the options. The owner picks. No subagent, no code.

The owner steers: this phase ends when they choose.
